## 0.1 Transcriber service skeleton
Read first: [architecture.md](../architecture.md) (layout, env vars).

1. `cd services/transcriber && uv init --python 3.11 --app`.
2. `uv add "fastapi[standard]" pydantic-settings redis rq python-ulid`
   `uv add --dev pytest ruff`
3. Create the folders from the layout: `app/{api,pipeline,jobs,storage}/` with `__init__.py`, plus `tests/`.
4. `app/config.py`: a `Settings(BaseSettings)` with the env vars from architecture.md, read from `.env`.
5. `app/main.py`: a FastAPI app with CORS from `CORS_ORIGINS` and `GET /health` → `{"status": "ok"}`.
6. `pyproject.toml`: set ruff `line-length = 100`, and pytest markers `model` and `eval`, both excluded by default (`addopts = "-m 'not model and not eval'"`).
7. `tests/test_health.py`: one `TestClient` test for `/health`.
8. Add `services/transcriber/.env.example`.

**Done when** `uv run pytest` and `uv run ruff check .` pass.

## 0.2 Docker for Redis, API, and worker
RQ workers rely on `fork`, which native Windows doesn't have. So the API and worker run in Linux containers, and the web app runs natively. The containers also provide ffmpeg and MuseScore.

1. `services/transcriber/Dockerfile`: `python:3.11-slim`, `apt-get install ffmpeg`, then install uv and `uv sync --frozen`. MuseScore is added in phase 2.
2. `docker-compose.yml` at the repo root with three services:
   - `redis`: `redis:7-alpine`, port 6379.
   - `api`: build `services/transcriber`, run `fastapi dev app/main.py --host 0.0.0.0`, port 8000, mount the source (for reload) and `./data`.
   - `worker`: same image, run `rq worker --url redis://redis:6379/0`, mount the same `./data`.
3. Both containers get `REDIS_URL=redis://redis:6379/0` and `STORAGE_LOCAL_DIR=/data`.
4. Update the infra commands in `CLAUDE.md` to `docker compose up` (all three services). Tests that don't need models still run natively with `uv run pytest`.

**Done when** `docker compose up` is running and `curl localhost:8000/health` returns ok.
